# 新供体 ROM 的快速适配

本流程服务于“已经适配完成，随后只给一个新供体 ZIP”的任务。默认复用本地最近验收的同机型供体分支；先读取已保存的基线登记，不反复要求用户提供已有信息。若本地缺旧原包、补丁来源或构建输入，明确指出缺项，先完成新包提取和差异报告，不能把知识文档当成完整构建环境。

## 一次性准备基线

每次验收完成就保存以下材料，以便下一次只需提供新 ZIP：
- 原始供体 ZIP、SHA256、机型/版本/区域、全量或增量类型；只读提取树及文件清单。
- 8T 硬件基线与工作中的 vendor/odm/boot/恢复组合、固件检查目录；供体更新默认不替换它们。
- 补丁账本：ID、状态、原始输入文件与哈希、输出哈希、脚本和工具版本、语义定位条件、预期修改次数、依赖补丁、回归项和回退产物。明确哪些是原厂文件替换、资源覆盖、字节码修改、配置调整。
- 当前活动镜像清单、分区预算、签名与构建配置（私钥仅本地）、无 ROOT 清理规则、userdata 预装清单及完整分包。
- 实机读回与发布 ZIP 的关联记录。临时实验和撤回方案不进入“自动复用”集合。
将这些位置登记到私有项目的基线索引，公开仓库只放结构和方法，不放 NAS 路径、原厂二进制或设备身份。

同一供体机型的小版本更新是快速路径；换供体机型、Android/API 大版本或关键 HAL/APEX ABI 变化进入迁移路径。名称都叫 ColorOS 16 不代表 ABI 不变，OS17 目前未验证。

## 接收新包

1. 校验文件完整性与 SHA256，提取 OTA 元数据、payload 清单及动态分区组信息；核对机型、地区、Android/API、安全补丁和版本，不能只按 ZIP 文件名猜。
2. 增量 OTA 必须有匹配的原始源镜像才能重建，不能当全量包直接提取。解包使用独立候选目录，保留链接、权限、SELinux 标签和 capability 元数据。
3. 对旧/新**原始供体**做差异，再对照补丁账本。不要拿“已修改旧系统”与新原厂包直接比较来判断上游修改。
4. 运行本技能的 donor_delta.py 建立文件差异与受影响补丁计划。文件相同可以减少重新定位；仍需检查 ABI、工具链、构建参数及依赖变化。文件被改名或移动时，先按包名/签名/类/资源语义寻找新位置。

## 迁移决策

| 情况 | 动作 |
|---|---|
| 原始输入和所有声明依赖未变、旧补丁已验证 | 候选复用旧修改件；验证缓存键、输出哈希和目标路径后纳入新构建 |
| 上游输出已具备修复行为 | 做正反例检查后退役旧补丁，不重复叠加 |
| 输入 APK/JAR/ELF 已变 | 重定位类/方法签名、资源 ID、符号或调用链；零匹配或多匹配即停止该补丁，不模糊套旧偏移 |
| 依赖改变、输入缺失、接口移除 | 标记为待迁移/阻塞，不能静默跳过后宣称功能保留 |
| 旧补丁属于临时/撤回 | 不自动合入 |
| 修改仅为 OEM 应用原始预装 | 使用新版完整 APK cluster；核对包名、版本、证书、split 与库依赖，保留原厂签名 |

可缓存重建后的 APEX/资源/修改件。缓存键至少覆盖**原始输入 SHA256 + 补丁版本/参数 + 工具链 + 签名配置标识 + 相关依赖哈希**；不能只按文件名或供体版本命中。签名私钥不进入缓存报告。供体固件不能替换 8T 硬件启动链。

## 本项目的优先复核点

- APEX 的 EROFS incompat 位、AVB/容器签名和对齐；不能给新 APEX 用旧签名块冒充有效签名。
- HWC/UHDR 能力声明、AOD 官方状态过渡、圆角/挖孔资源；新 feature 配置可能再次覆盖旧修复。
- 指纹照明、Richtap 协议、三段键 feature；声明与实际 HAL 保持一致。
- 小布应用更新与系统兼容分开：原厂唤醒 APK/JNI/ODM/DSP 配套必须成套；AI 实景入口或小布通话内部/云端判断不保证永久免维护。
- Settings/MOD、Launcher 返回小布圆角、应用找回、相册实况限制：逐项追踪类、资源和行为，不把整个旧 Settings/Launcher 覆盖到新供体来“省事”。
- [userdata 预装](native-preload.md)中的 loop 挂载、PackageManager cluster 复制、重复包优先级、PMS 路径清单及升级/卸载记录。
- 最终固件前置检查、当前槽位、完整 super 元数据、无 ROOT 清理以及无自动 Format Data 规则。

## 构建和验收

保留供体新增功能，合并最小已验证兼容处理；生成变化清单、未合入项和缺失功能列表。按受影响项扩大回归，不靠减少特效或功能取得性能提升。

所有版本都验证离线完整性、首启/重启、关键硬件冒烟、TWRP/当前槽位、完整包读回。受影响功能追加实体测试；性能比较使用相同冷启动应用、温度、亮度、刷新率、投屏状态和动画档位。系统更新至少验证一次同系列覆盖安装保留笔记/设置/应用数据，预装变化需验证干净首启、split、用户卸载后不意外复活及完整资源恢复。用户手动清数据，不由包自动清除。

完成后更新基线索引、补丁账本和缓存，让这次新版本成为下一次输入。交付新 ZIP、校验值、功能变化、已验/待验矩阵及回退方法。快速适配意味着少做重复逆向，不意味着省略必要实机验证。

## 只读差异工具

```text
python scripts/donor_delta.py snapshot /old/pristine-tree --label old-stock --output old.json
python scripts/donor_delta.py snapshot /new/pristine-tree --label new-stock --output new.json
python scripts/donor_delta.py plan old.json new.json --patches patches.json --output plan.json
```

以上 scripts 路径相对技能目录。工具不解包 ROM、不应用补丁、不连接手机、不保证功能兼容。snapshot 输入为静止的已提取树；权限、SELinux 和 capability 由解包工具独立保存比较，不在此文件内容清单覆盖范围内。输出使用相对路径，不记录主机根路径。plan 不因存在待迁移项而退出失败；消费者必须检查 ready_for_candidate_reuse，它也仅是输入级候选资格。

补丁账本最小格式（示例路径，须替换为工程实际文件，并声明全部相关输入）：
```json
{
  "patches": [
    {
      "id": "native-preload",
      "state": "verified",
      "inputs": ["system/framework/oplus-services.jar", "system/etc/init/hw/init.rc"],
      "depends_on": [],
      "tests": ["clean boot", "split APK", "upgrade preserves data", "uninstall then reboot"],
      "recipe": "local versioned patch entrypoint"
    }
  ]
}
```
只读工具检查 inputs、依赖图和状态；recipe、输出哈希和语义后置条件由本地补丁构建器负责。新增补丁可以用 state=experimental 登记，不能伪填 verified 以获得复用资格。
