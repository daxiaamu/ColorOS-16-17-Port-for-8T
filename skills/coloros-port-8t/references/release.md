# 产物、TWRP 和发布回归

## 清单是依据，不是脚本名

保存供体、目标基线、输入/输出 SHA256、文件长度、修改条目、候选标签、实机读回结果。分区的历史 dev 编号可以不同；PKX 与 PMD 的编号不是同一个序列。冻结活动镜像清单后构建完整 super，不能再让构建树自动指向最新实验。

历史本机 super 为 7,516,192,768 字节，动态组上限 7,511,998,464 字节，dev31 快照对齐后剩余约 1 MiB。这些仅用于解释容量压力，不可作为其他设备的写入参数。镜像逻辑长度、稀疏传输大小和动态分区分配大小分别计算。

## 校验脚本输入

`verify_image_manifest.py` 接收下面这种自建清单，路径相对 `--root`：

```json
{
  "alignment": 1048576,
  "group_limit": 7511998464,
  "partitions": [
    {"partition": "system_ext", "path": "system_ext.img", "bytes": 4096,
     "sha256": "填入该文件的真实64位十六进制SHA256"}
  ]
}
```

示例长度不是 ROM 的真实长度。工具接受展开后的原始镜像，拒绝 Android sparse 输入，避免把传输大小当成逻辑分配大小。脚本会拒绝错误哈希、重复/未知分区、路径逃逸和容量溢出；不要求清单必须包含所有动态分区，因此 `PASS` 仅对列出的集合有效。完整包需另外检查必需分区集合、super 元数据、文件系统兼容和设备匹配。

## TWRP 完整包

- 当前策略要求先刷好官方 8T OS13/14。本包不含、不写 XBL/XBL_CONFIG、ABL、modem、TZ 等底层固件，DDR4/DDR5 启动链均保留。氢 OS11 直接切换方案已放弃，不沿用历史全固件包。
- 安装前检查目标身份/硬件变种、解锁状态、动态分区/槽位、snapshot、电量、恢复工具和内存。验证全部 payload 后才开始任何分区写入。
- 本项目安装包不得自动格式化 data/metadata。首次安装由用户在 TWRP 手动 Format Data，重启恢复环境后刷 ZIP；刷后再次格式化会删除预装资源。升级保留数据，data 不可读或兼容标记不符时在写入前退出，不得自动清空。
- 启动属性与 Boot HAL 交叉验证，A 刷 A、B 刷 B，启动原槽。共享 super 重建会清空未用槽的逻辑系统，不提供另一槽旧系统回滚；其他槽启动镜像和底层固件不写。
- 大镜像可采用有界分片或 payload/img，必须有每片及整体完整性检查。分片大小由恢复环境和可用内存决定。
- 刷后按镜像有效逻辑长度读回校验，并验证启动、真实功能和恢复环境。

源码、本机 APK、候选镜像、已刷入增量、发布 ZIP 分开验收。不存在从原厂 ZIP 到所有补丁的全链路自动构建时，明确写“整合已验证镜像”，不要宣称完全可复现。

## 底包检查与恢复问题

从各官方 OS13/14 包提取关键固件并按 DDR 类型去重，当前槽 19 项必须匹配同一参考集合。当前语料 60 个可读包、88 个组合，未知/混合固件不放行。扩充清单核验原始包与 payload 长度/哈希，不能用供体系统安全补丁代替硬件固件证据。

工程号 19805 为该硬件关键证据，旧官方 bootloader 的 codename 可能为 instantnoodle，不能仅因不是 kebab 就误拒绝。snapshot 检查真实 dm target、metadata state 与 holders；unused linear system_b-cow 名称本身不能证明活动快照，也不能因此关闭真正的快照检查。

TWRP 提示中文一行、英文一行，两行均刷新。Sideload 结束不是成功判据，以完成记录和实际刷后状态为准。Color597 TWRP data 解析及 reserve loop 修正见 [native-preload](native-preload.md)。

## 回归矩阵

| 层级 | 最少需要的证据 |
|---|---|
| 离线 | ZIP CRC/重复条目、DEX/ELF、权限/标签、APEX 格式/签名、分区预算 |
| 临时 | 当前输入哈希、唯一 backing file、目标 mount 表、退出回退；不覆盖正在 bind 的源文件 |
| 固化 | 源镜像哈希、目标范围、整镜像读回、无临时挂载依赖 |
| 启动 | boot_completed、核心进程稳定、启动新增错误和服务依赖 |
| 实体 | 显示/AOD/指纹/振动/三段键、声音路由、充电电流 |
| 应用 | 拍照/录像/相册编辑、恢复服务、通话、互传、MOD 持久化 |
| 性能 | 同条件真实冷启动、动画帧时序、线程/锁原因 |
| 完整安装 | 指定底包逐一清空安装、首启、data 预置、出厂恢复、TWRP/槽位 |

UI 抓取先删除工具自己的旧 XML，失败即停止读取旧结果；核对前台页面。命令完成或没有新 crash 不代表用户可见效果通过。时长/性能样本必须注明是否含轮询与 trace 开销。

## 公共资料

优先公开整理后的方法、补丁目标、来源和脱敏结果。设备序列号/IP、IMEI、MAC、账号、校准备份、原始 traces/logcat、通话和照片、私钥/令牌不得混入分享目录。不要直接 git add 整个私有工程。

默认 USB 调试/ROOT 是构建配置选择；面向公开发布应明确其状态。不得预置信任开发者 ADB 公钥。许可只覆盖有权发布的原创内容；OEM APK 和上游代码的权利不能靠添加 MIT 文件覆盖。

## 扩容 super 与冻结发布版本

安装器容量门槛应来自本包所需的有效范围。本次 8T 包将“恰好等于 7,516,192,768”改为“大于等于”，并检查 blockdev 返回为有效数字和 4096 字节对齐；小于需求或异常值在写入前退出。离线覆盖原厂大小、更大、偏小、未对齐、非法和空值六种情况。扩大物理容量不应被直接判为不兼容，但仍要独立验证逻辑元数据、分区组预算、设备身份及固件。

本包重建共享 super 的逻辑布局，不修改 GPT，不自动利用超出原厂大小的尾部容量，也不保留用户自定义逻辑分区大小。扩大设备是否真正可刷仍需实机验证；“比较符已改为 >=”不能代表扩容验收。

发布版本改变时生成新不可变快照，不原地覆盖已校验或正在上传的 ZIP。核对三处：文件名、MOD 卡片、关于本机；保留真实供体版本在来源清单中。协议属性含非 ASCII 文本的故障见 [扫一扫案例](scanner-camera2.md)。

本轮交付检查覆盖所有载荷哈希、ZIP 内容、A/B 元数据、无 ROOT 启动镜像、当前槽策略、无自动清数据、中英提示、附件字节一致性及无包内安装说明。下载目录读回 SHA256 与构建记录一致后才交付。更新日志只列本轮改动，并分开候选镜像测试、最终 ZIP 安装和仍待验证项目。
