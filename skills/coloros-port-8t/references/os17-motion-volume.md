# 晕动舒缓与 300% 音量：声明不等于硬件结果

## 晕动舒缓 dev38

开启后无点阵，绘制层虽存在但回调注册集合为空、alpha=0。8T 缺少供体的传感器 33171091/33171092；不是把 alpha 强制为 1 就能修复。

限定 KB2000 且原传感器缺失时，复用标准线性加速度 type 10，以 20000us 采样；自动乘车使用 wakeup CMC 33171035，按已核对的原厂事件协议映射进入/退出。保留原有绘制、旋转、过滤与生命周期，不能伪造运动事件。Settings 同时修复自动模式退出页面后被重置，展示原有两种模式；其它设备保留原路径。协议细节参阅 [OS16传感器经验](motion-relief.md)，OS17 方法签名和事件链需重新核验。

三个框架类与一个 Settings 类变更；全 DEX 往返和两分区审计、完整回读通过。手动/自动/关闭/重开/息屏注销/唤醒恢复六项验证，20000us 注册和真实运动事件可见，用户确认圆点随运动变化。实际车辆进入/退出准确率与延迟未验证；不据此声称自动乘车场景已全部通过。

测试后恢复原用户模式和息屏超时，不把诊断现场选项固化为用户默认值。

## 300% 音量 dev39

OS17 AudioServiceExtImpl、libaudiopolicyextimpl 与 Settings 已有同一原生分支，仅在 system_ext 的多媒体 feature XML 中增加 oplus.software.audio.super_volume_3x。

重启后原生能力查询 3x=true，2x/4x/multilevel=false；音量设置未变。未改增益表、音频库或温控，没有播放最大音量或测声压。这个结论是恢复能力声明，不是实测声压三倍。以后适配先检查原生实现与底层支持，不批量强开所有倍率。
