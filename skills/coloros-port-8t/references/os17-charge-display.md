# 闪充动画与状态栏颜色：协议显示兼容

适用现场：KB2000 官方 14.0.0.602 充电协议策略配 OS17 展示框架。dev46 已安装；真实 65W 适配器、蓝色图标与充满过渡仍待实体测试。

## 两条独立链

框架缺少旧硬件协议展示回退；SystemUI 又因产品 launch API 为 35、板级为 30，把 8T 的旧闪充特殊颜色门槛挡住。不能通过改全局首发 API 同时影响相册、相机等消费者，也不能直接把所有 USB 充电标成 SUPERVOOC。

## 框架回退条件

在 OplusBatteryServiceFeature.getChgConfig 调用原 HAL 恰好一次后，仅当原返回字符串严格为 "0"，且 query 为 0/1/4、caller=1、extra 为空、机型 KB2000、HAL 类型 6、充电技术 support=3、AC online=1 时使用官方策略回退。

复用经过官方包核对的协议/适配器/功率映射，最高封顶 65W。query 1 保留低于本机最大瓦数时隐藏的原策略；query 4 返回封顶后的原始瓦数供颜色判断。未知协议返回 0；原生非零、-1、null、空字符串及异常处理保持原意。不要补成通用的“错误都当快充”。不写充电控制、温控、电流或功率节点。

## SystemUI 门槛

只对 KB2000 的 isChargeVoocSpecialColorShow 分支使用 ro.board.first_api_level，缺失时回退原产品值。当前供体对应 StatusBarFeatureOption 合成 lambda 的 id=8；这是定位线索，不是跨版本稳定接口，别连同 id=9 等分支一起替换。

保留原色彩资源与充满逻辑：当前原生规则至少 33W 为蓝、至少 100W 为紫；8T 回退封顶 65W，不伪造紫色功率。新增寄存器时保留原 true/false 常量寄存器，验证所有分支类型。

## 已验证与未验证

- 只改一个框架类和一个 SystemUI 类；完整 DEX 往返及 ZIP 差异检查通过。
- 从实际方法构建的 669 项协议/query 用例及 17 项限定条件用例在设备 ART 通过；隔离映射/mock HAL 不写充电硬件。这不是 686 次真实充电测试。
- 两分区完整回读、重启、运行文件哈希通过；特殊颜色开关由 false 到 true。
- 普通 USB 下技术 0、wattage 0、superVooc=false，未误判快充。
- 等待实体 65W 测试的采样器超时，未取得 AC 样本，已移除临时采样文件。动画、颜色与充满实测不可标完成。
