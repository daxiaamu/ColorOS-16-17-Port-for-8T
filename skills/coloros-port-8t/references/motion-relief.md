# 晕动舒缓显示与自动乘车识别

## 适用范围与证据

在 PMD110 16.0.10.501 供体与 KB2000 旧硬件组合上，开关可见但没有点阵。手动显示已获实体确认；自动识别的原生 UI、真实传感器注册和息屏生命周期已验证。实际乘车进入/退出的准确率、延迟仍待乘客测试。候选 system/system_ext 已刷入并读回验证，既有 r15 ZIP 尚未包含这些修改。

## 先区分绘制与输入

原供体依赖运动传感器 33171092 和车辆场景传感器 33171091，8T 不提供这两个类型。注册失败发生在回调保存前，因而绘制视图即使处于运行状态，也没有有效输入，点阵透明度保持为零。不要通过强制 alpha 或伪造运动掩盖缺失输入。

仅在已确认的 KB2000 且原运动传感器缺失时，使用标准线性加速度 type 10，采样周期 20000 微秒。把实际 x/y 映射到原生绘制算法 mode 0 所需数组的索引 1/2，继续使用原有旋转、过滤、阈值和绘制生命周期。这里的 10 是传感器类型，不是下文的 CMC 事件值。

## 自动识别复用官方 CMC 协议

从本供体原厂 DeepThinker 的 SensorHub.java、InCarDetParser.java 和事件定义交叉确认：

| 输入/接口 | 语义 |
|---|---|
| cmc_oplus wakeup，类型 33171035（0x1fa265b） | 8T 实际提供的旧乘车识别传感器 |
| CMC values[0] 转整数为 10 | 进入车辆 |
| CMC values[0] 转整数为 0 或 5 | 离开车辆 |
| 其他 CMC 值 | 忽略 |
| DeepThinker 事件 300，状态 0/1 | 进入/退出 |
| AntiDizzy 场景回调值 1/0 | 在车内/离车 |

这些数值属于不同协议层，不能直接透传。用 getDefaultSensor(type, true) 显式请求 wakeup 传感器；不带 wakeup 参数的调用可能返回空。传感器 handle 是本次运行的证据，不应硬编码。

兼容分支限于目标硬件且原场景传感器缺失。复用原生 handler、注册集合、模式切换和回调，把真实 CMC 事件映射到原生场景通知。不添加 GPS、蓝牙启发式判断或常驻分类服务。

## 原生设置页会撤销自动模式

本供体 MotionSicknessReliefSettingFragment 的 initViews 在恢复页面时把自动模式改成常驻，并关闭已开启的总开关；XML 中两个现成模式条目也不可见。先与实际发布 APK 和原供体比较，避免误归因于历史补丁。

本次仅调整该类的 initViews/updateModePreferences：保留有效模式、移除强制重置，按总开关显示已有 COUIMarkPreference 与原有监听器。无需重写页面或改资源。原生入口为“辅助功能 → 晕动舒缓显示”，模式为“仅车辆运动时显示”和“常驻显示”。

## 验收与新供体迁移

- 手动模式：实体点阵、方向响应；不注册 CMC。
- 自动模式：通过原生 UI 选择，真实 CMC 与运动输入均注册；页面重开不关闭开关或改写模式。
- 关闭/息屏：解除两种注册；亮屏：保留自动选择并恢复两种注册。测试临时延长的息屏超时须恢复。
- 实际乘车：以乘客身份验证进入、退出、延迟和误报；桌面注册成功不能代替。
- 新供体：重新确认缺失的传感器、协议映射、Settings 是否仍强制重置；官方已修复的分支应退役，不盲目重放旧方法体。
- 对实际发布 DEX 做语义差异检查；本次框架仅三类代码变化、Settings 仅一类变化。去除 DEX 调试元数据以适应分区预算时，应另验其他方法指令不变。
