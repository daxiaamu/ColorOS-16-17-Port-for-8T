# 补丁复查、退役与合入

先确定当前设备的分区哈希，再确定待合入候选。历史脚本存在不代表仍生效；构建成功也不等于最新修复已进镜像。保持已安装基线、候选和完整ZIP三种状态分别记录。

本次复查确认早期启动500ms延迟和显示200ms插桩早已从干净基线重建撤回。最终services/oplus-services中不含对应诊断标记。新版山之道只保留缺初始尺寸布局的一次性回退，临时着色器和帧日志已恢复；不能因ASTC报错仍出现就盲改解码器。

旧userdata reserve循环挂载已被Super内只读bind替代。最终init保留一次正确挂载；原厂OTA创建同名目录不是旧方案继续运行的证据。不要误删其原有行为。

明确退役补入的旧Nature05山之道索引，保留新版在线三款。保留旧素材以免破坏其它引用和已有用户选择。高级重启从单选列表换菜单后，比较生成类集合与合并DEX，确认没有遗留旧helper类；Settings只使用最终带图标候选，不能重新从旧构建树覆盖构造函数或关于遮罩修复。

旧内核BPF、VNDK、HIDL启动控制、面板能力、Wi-Fi空值和缺失QSPM HAL各自解决不同故障；有证据和范围控制的兼容层不是无效叠加。不能为了补丁数量少而恢复已证实的崩溃或永久等待，也不能把尚未验证的硬件功能称为全部完成。

用户要求默认动画等级保留3；不要因某次诊断现场为1就替用户改变缺省或已保存选择。AOD缺省0是另一项明确要求，两者独立。

## 合入检查

- 从当前每个分区的确切输入构建。硬链接文件先断链再写，旧候选不可原地修改。
- 对APK比较全部ZIP条目，限制变化DEX和新增资源，做语义往返及ART/真实页面回归。
- 对新分区比较完整清单，检查内容、inode和SELinux标签。审计报告必须覆盖所有目标分区：换临时盘后若路径未适配，空标签报告会假通过，必须拦截。
- 所有目标分区的旧哈希、容量、槽位、快照和挂载检查在第一次写入前完成；逐分区读回，并核对boot和Super元数据未变。
- 用户数据不需要因UI/资源更新清除。新完整ZIP必须另行打包校验，不能把旧dev24 ZIP改称新版本。
- 临时ROOT授权结束后撤销Shell权限并验证su失败，再卸载临时管理器；不能只卸载管理器却留下授权。

## 小幅逻辑容量不足

物理Super足够不代表现有逻辑分区放得下新镜像。本轮system_ext增加192 KiB，容量检查在任何镜像写入前拦截。fastbootd扩容返回分区表写入失败后，完整比对元数据确认未变，再离线核对相邻对齐空隙。仅在备份、各槽主副本校验、范围与组预算、其它extent不变均证实后，利用现有空隙延长目标extent；重进recovery确认映射并再次校验原分区内容。该现场方案不是通用扩容工具，不能照抄大小或偏移用于其它布局。

## 本轮工具链与运行验证的坑

- 宿主 D 盘满后转 E 盘构建，连同 source-case、审计路径和当前基线一起更新。新 my_product 用 dev45 源树，但总镜像清单继承 dev46，防止把新闪充的 system/system_ext 换回旧版。
- Python 3.8 的 Path.write_text 不支持 newline 参数；LF 脚本用明确 UTF-8 字节写入。控制台/文件均显式指定 UTF-8，避免中文路径或内容被宿主默认编码破坏。
- mkfs.erofs 曾中途退出；失败留下的文件不是可刷镜像。保留失败日志、核对输入后再构建，成功后仍做内容/inode/标签审计，不能只看文件非零。
- TWRP 的 ADB 状态为 recovery，不能只用等待 device 状态的方法判定离线。指定目标序列号，有限轮询 ro.twrp.version；不重置全局 ADB server。
- APK 改过 DEX 后保留原 Signing Block 只能维护本开发系统的分区兼容元数据，不能声称拥有有效原厂内容签名。新路径重扫、实际重启比旧缓存下能启动更有意义。
- 当 UI 被锁屏或签名权限保护挡住时，记录待用户解锁/从正常入口进入；不改系统权限来制造“实测成功”。测试模型/模拟 HAL、原生服务状态、实体反馈分别记证据。

## dev67 构建整理

完整包入口使用显式镜像清单、boot 输入目录、输出目录和显示版本；构建前验证 15 分区全集、重复项、长度/哈希、对齐和组预算。分开运行 Super 构建、载荷验证/分片、安装器测试、打包及 ZIP 验证，不再通过读取旧构建脚本、字符串替换后 exec 来继承流程。旧脚本保留历史证据，当前入口转调统一构建器。

校验显示版本必须读取固定 my_manifest 镜像；仅包名和 JSON 一致不足以证明系统版本一致。继续沿用 OS16 安装器的设备、固件、快照和读回检查，以及 OS17 Super 容量提醒；不自动扩 GPT、不格式化 Data。A/B 12 份元数据、全部 ZIP 载荷哈希和 CRC 各自验收。该流程是已验收镜像的可追溯整合，不是从 OEM 源码完整重建。

山之道现有 RESIZE 处理的 1080×2400 是设计基准，真实 size 与比例另行计算。不能把设计基准全部替换成物理屏尺寸。尚无已核实的无 RESIZE 时读取实际 Viewer 大小接口，因此本轮保留一次性初始布局，后续真实 RESIZE 仍优先。
