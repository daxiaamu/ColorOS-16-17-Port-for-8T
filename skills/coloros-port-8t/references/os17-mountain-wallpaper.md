# OS17 山之道切换后桌面与锁屏黑壁纸

## 现象与证据

本次选择的是在线新版 `theme-OS17-4000-mountain-common` 的 mountain01；桌面、锁屏壁纸全黑，图标和时钟正常。不是补入的 OS16 Nature05 重复索引。现场动画等级已经是1，也不能把 OneShot 等级门槛当成本次根因。

原生壁纸引擎进程存活，序列帧播放到末帧，山体透明度为1。实际加载的182个文件与主题源一致。Adreno650独立探针能上传、采样同一张6x6 ASTC帧；45个着色器独立编译通过。这些检查只排除了相应路径，不证明完整场景渲染正确。

预览和引擎里出现 `unsupported ASTC block size 3x3`，但不能据此修改解码器或拒绝合法纹理。最终合成器改为短暂纯色输出时可见，而前景画面仍黑。随后发现没有发生主题依赖的 VIEWER/RESIZE 布局回调，中间渲染纹理未初始化。补做初始布局后，用户明确确认桌面与锁屏均恢复。

## 最小修复与边界

对这个已核对版本的 WeatherEntry，在 onStart 完成原有初始化并回放待处理事件后，仅当 screenInfo 仍为空时补做一次布局。目标是8T，初始尺寸使用该设备的1080×2400；保持原有后续 RESIZE 处理。不要每帧重建纹理，不要停用天气、时钟、全景或原生帧率控制，也不要强行修改所有机型的尺寸。

这是当前宿主与主题初始化生命周期的兼容修复；还没有确定宿主没有投递尺寸事件的更底层原因。旧版引擎、更新版主题或其它屏幕尺寸应重新取证。

## 固化资源

本次内置来源是 my_product 的 `decouping_wallpaper/common/wallpaper_group/coe2_coz_weather/weather.coz2`，配套 `theme.version`。容器开头为 COZ2、版本和解压长度，后接 LZ4 frame；解压内容为 L4D1、条目数量及逐项名称长度/数据长度/名称/数据。必须校验实际结构，不把本次格式当作所有 COZ 的通用规格。

本版本685个条目仅替换 WeatherEntry，逐项校验其余684个资源内容和顺序不变。新容器重新解压校验，并让原生引擎实际加载；同时提高配套资源版本，使旧解包缓存刷新。仅改 Data 缓存不能作为整包修复。严禁覆盖硬链接构建树中的源文件，应先断链再替换。

当前手机的原生引擎已成功解包修复容器，缓存升级到1029且脚本逐字节匹配。候选分区与dev32仅两处文件差异，内容3722文件、inode4529、标签4532的审计均无差异。dev34已刷入my_product并完整回读通过，正常重启后系统资源与缓存哈希匹配，临时bind不再存在；用户确认另两款山之道切换也均正常。临时Shell ROOT已撤销，管理器已卸载。

## 临时诊断收尾

私有主题缓存需获得明确授权后通过临时ROOT读取，原始归档留在私有工作区。不要上传主题素材、APK、账户缓存、密钥或原始个人日志。修改前备份；纯色输出、帧日志和所有临时探针都要恢复。修复验证后撤销Shell超级用户权限并卸载仅为诊断安装的管理器。设备命令始终指定8T序列号，禁止触碰一加15。
