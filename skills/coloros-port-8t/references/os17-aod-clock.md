# 全景息屏与锁屏到桌面时钟：分开诊断

全景息屏的默认/增强效果与锁屏到桌面灵感时钟OneShot是两条机制。用户要求AOD初始为“默认效果”，不能因此把时钟交接也关掉，更不能让两个开关互相强制改值。

## 实体黑屏与内核依赖

本次增强AOD模式下Power/Display显示DOZE_SUSPEND，但实体全黑。只将`port8t_aod_seamless`从1切到0后，用户确认可见壁纸/时钟。证明默认路径可用，不证明增强路径已修复。

后来确认保留的boot内核早于OS16 AMB655X累计补丁。应比较当前实际kernel、DTB、ramdisk、源码与累计补丁；版本后缀或曾经编译过并不能证明正在运行它。单独v9增量片段不等于从原厂基线可用的完整累计补丁。配套内核经临时启动验证后再固化，不能让系统能力先启用而内核依赖缺失。

默认0候选同时修SystemUI策略和Settings缺省值，保留用户已保存的0/1；不要强制覆盖选择。smali改getInt默认值时，检查同一常量后续是否还用于“是否等于1”的判断。本次需要在读取后恢复该常量，避免默认变化意外反转已保存值。

## OneShot成功证据与当前回归

曾捕获锁屏/解锁原生状态：UNLOCK_PENDING_READY → UNLOCK_ANIM_KEYGUARD → UNLOCK_PENDING_RELEASE → IDLE，Surface交接并正常释放，用户随后确认效果正常。没有额外时钟补丁。`send timeout msg`只代表安排超时任务，不能当作超时发生；静态`canOneShotTransition=false`也可能只是当前阶段状态。

2026-09-20再次报告无效果，实测时钟仍为`com.oplus.keyguard.clock.digital`，省电0，但`persist.sys.oplus.anim_level=3`。旧成功记录为1。原生OneShotAnimState在构造函数缓存这个属性：显式等级>2返回不支持；未指定时走platformGaussianLevel分支，不能把两个等级数值的方向混为一谈。当前桌面回报不支持且无时钟位置数据，与门槛一致。

dev22和dev32的my_product默认都为3，性能修复没有改该值。清装恢复默认可以解释回归，但没有确定用户配置变化的精确时点。恢复先前等级1并重启/重建相关进程后再验收；本次只诊断，尚未执行该回归。仅setprop后看值已改不证明缓存已更新。

## 按实际运行条件排查

1. 核对主用户、原生默认锁屏、省电、动画等级、OneShot feature/property。
2. 核对应用后的时钟包，不只看主题索引。旧山之道模板声明clock.big，原生OneShot需要clock.digital，但本次现场已是digital，因此不能只凭模板就下结论。
3. 桌面需有可交接的灵感时钟位置与布局；记录桌面支持回答、时钟布局数据和Surface生命周期。
4. 分开息屏、亮屏、滑动解锁的时间窗，等待各阶段稳定后复现。临时日志开关保存原值并恢复。
5. 记录握手、释放原因和用户实体观感；若只是时钟字号、模板或页面变化，不强行绕过原生能力门槛。

抬起不亮屏的另一反馈在用户启用原生“抬起唤醒”后解决，用户已停止该项调查；不因此补丁传感器或常亮逻辑。


2026-09-20用户明确确认默认动画等级3没有问题，要求保留。后续现场读到已保存等级1，但没有据此改用户设置或强制新默认；本轮将缺省改1的未刷入候选已撤销。默认策略尊重该要求，诊断时按实际运行状态验证，不把山之道布局修复误记为等级调整。
