# 充电上限和旁路供电

## 区分控制点

现代充电 HAL 的 `chg_up_limit`/`plc` 接口可能不在旧 8T 内核中。先检查实际节点、HAL 参数与返回、旧驱动实现，再考虑映射。UI 变为开启、设置数据库变为 1、sysfs 回显 1、真实电流变化是不同层级。

本项目在充电 HAL 进程内使用有限作用域兼容库，将缺失的新接口映射到旧 `mmi_charging_enable`。原生新节点存在时优先走原生路径。不更改温度、电流、电压或过热关机保护，不伪造电池状态。

## 所有权和共存

充电上限与旁路各自保存“需要停充”的原因，任一仍要求停止时不能恢复充电。只有兼容层自己成功停止并读回确认过的状态，才有资格在条件解除后恢复；不要接管温控或未知进程的停充。

检查 SOC/在线状态/MMI 输入有效性，加入有意义的阈值滞回，先读回再提交内部状态。拔电、HAL 重启、系统重启是不同事件。运行 checkpoint 必须关联本次 boot，不能跨重启错误继承停止归属；恢复出厂应消除用户设置。历史源码存在 checkpoint，不代表当前镜像中的库就含有它，必须核对生产 ELF 哈希。

## 旁路试验的证据强度

旧驱动的停止电池充电与 USB 输入 suspend 是不同动作。测试曾看到停止充电后电池电流接近零、外部输入仍存在，恢复时电池充电恢复。这只证明当时负载下的供电/停充行为，不证明电池电气隔离或满负载旁路。

旁路候选已实现实际 native PLC 请求 `switch=0/1|callname=...` 的严格解析，并通过隔离 open/write/close 测试、同 boot checkpoint 恢复和有界真实 HAL API 开关试验。以上为早期隔离试验。20260915 已将后继兼容库合入完整包，原生开关的电流对照获用户验收；停止归属、上限/旁路共存和无效电流样本处理须随库一起保留。最终 ZIP 的整包重刷尚未复测，不能扩大为任意充电器、负载和完整温度周期均通过。

## 建议测试顺序

1. 离线/隔离测试：阈值、滞回、非法输入、重复请求、充电上限与旁路共存、外部所有权、拔电与 checkpoint。
2. 有界实机试验：明确原有上限/旁路选择、电量、温度、适配器能力；保存原库与状态，设置超时和退出回退。无需重置全局 ADB。
3. 原生页面操作确认实际请求与电流；上限开/关组合，不同 SOC、拔插、HAL 重启。
4. 合适适配器与可控负载下长测；确认无额外升温和供电不足。电流正负和单位因节点而异，先用正常充电确定语义。
5. 固化、完整重启，再验；最终恢复用户要求的充电上限。

不把隔离夹具的模拟 SOC、电流返回或 test-only 初始化动作混入生产逻辑，也不以其冒充真实充电周期。高能户外/智能极速充电/温控 UI 是否存在不代表旧硬件具备相应电气能力。
