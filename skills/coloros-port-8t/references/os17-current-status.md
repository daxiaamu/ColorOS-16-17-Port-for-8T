# ColorOS 17 实测状态与验收边界

更新：2026-09-20。本分支记录 OnePlus 15 PLK110 → OnePlus 8T KB2000 的开发移植。供体为 PLK110_11.C.61 对应 ColorOS 17.0.0.100(SP09CN01)，Android 17/API 37；目标使用经过验证的 8T 4.19 内核与硬件底层。离线分析供体包不意味着可以操作供体手机。

先读本页，再按 SKILL.md 路由阅读。本文优先于同目录 ColorOS 16 历史记录中的“ColorOS 17 尚未验证”，但不把 OS16 的硬件、DDR、固件覆盖面自动扩展到 OS17。

## 三个不同的状态

| 层级 | 已有证据 | 不代表什么 |
|---|---|---|
| 完整开发包 dev24 | 实际 TWRP 整包安装、写入范围读回、经用户授权 Format Data 后正常首次启动 | 不是 enforcing、无 ROOT 或所有硬件验收完成的正式版 |
| 当前设备增量状态 | dev24 后叠加 dev30b 分享修复、dev32 语音/Perfetto 修复；相应分区读回通过 | 旧 dev24 ZIP 不会自动获得后继修复 |
| 后继候选 | AOD 默认0、MOD菜单/图标、版本日期、旧山之道去重已完成离线候选 | 未合入镜像或未刷入的内容不能称实机完成 |

dev24 完整 ZIP SHA256：`5447eb8fdf12f0315163fd03af76354f01621bd99b51e11740fb81f9979c3565`。这只是历史开发产物的身份锚点，本仓库不提供该 ROM。清装首启约198秒，不能用首次 dexopt 阶段衡量日常性能。开发 boot 为 permissive，含既有 ReSukiSU 内核基线；不继承 OS16 的“无 ROOT 发布”结论。

## 已完成与仍需验证

- 已开机；启动故障的处理见 [启动与框架](os17-boot-framework.md)。日志中的 boot_completed、稳定进程、实体屏可操作是不同证据。
- MOD 入口、关于顶部卡片、主题栏目与全景息屏显示设置已恢复；卡片遮罩修复实机可见。
- 预装安装源回到 Super；44个迁移文件的哈希和只读挂载已验证。已有 /data/app 实例仍属于用户数据；清装后的全部44文件复核未作为本轮完成项。
- 无线充电共同能力声明已纠正，设置与磁贴入口均验收；有线反向充电保留。
- 互传控制中心入口添加/移除/重加通过；后继普通分享入口修复获得用户“可用”确认，不等于 agent 观察到真实文件传输。
- 分身上限20，原生边界探针与设置文案通过；没有创建并启动全部20个分身。
- AOD默认效果实体显示通过；增强无缝模式有配套内核依赖，不能只以DOZE状态或截图验收。
- dev32语音服务连续约12分钟未再出现原先Java崩溃、PID稳定；未完成实体语音唤醒功能测试。Perfetto重启后正常并成功追踪。
- 锁屏到桌面时钟曾有原生交接和用户成功反馈；最新等级3触发原生关闭条件，恢复等级1并重启的再次验收尚未执行。
- 原有无线子系统原生空指针崩溃、部分解锁长帧、完整 enforcing 和广泛硬件回归仍未闭环。
