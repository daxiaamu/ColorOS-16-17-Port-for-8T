# 增量 OTA 还原：A.72 → A.73 → ColorOS 17

适用：用户提供升级包而非完整分区，或认为小前置包只改版本号可以略过。

## 按哈希决定是否需要前置包

本次 C.61 payload 要求 A.73；SOURCE_COPY、BROTLI_BSDIFF 等操作依赖旧分区。A.72 的部分分区匹配，但 system/system_ext/my_product/my_stock 不满足 C.61 的源哈希。A.73前置包约155MB，实际有必须还原的系统分区变化，不能凭大小或“仅锁bootloader/改版本号”的资料跳过。

1. 保存 OTA metadata、每分区源/目标长度与哈希、payload properties、操作类型清单。
2. 对每个所需分区逐一校验源哈希；相同的分区才可直接复用。移植过的8T镜像不能充当未改动供体源镜像。
3. 先还原 A.73，再将通过校验的结果作为 C.61 源；每一级输出都检查最终目标哈希。本次11个选定系统镜像完成该闭环。
4. 区分下载完整性和可信签名：payload内嵌哈希匹配只证明内部完整性，不独立证明OEM真实性。
5. 供体boot、vendor、odm、dtbo等硬件内容即使能还原，也不是8T刷写候选。

## 容易漏掉的 dm-verity 范围

初次还原只完成数据操作，漏掉 manifest 描述的哈希树生成范围，最终 system 哈希失败。修复是按算法、salt、数据/哈希树extent生成完整输出，再验目标哈希；不是放宽校验。工具应拒绝未实现的FEC或操作码，失败结果保持partial状态。

BSDF2/Brotli差分解析要核对实际格式与边界；不能将一种BSDIFF容器处理器当成所有payload算法的通用实现。保留未修改供体树和移植树两套索引，后续供体更新按语义重定位，不沿用旧版本偏移。
